## 状态流转说明

```
待调研 ──→ 调研中 ──→ 调研完成 ──→ 已核验
                              │
                              └─ 存在 ❌ 项时退回「调研中」，修正后重跑
```

| 状态 | 含义 | 进入条件 |
| :--- | :--- | :--- |
| `待调研` | 已列入批次，尚未开始 | — |
| `调研中` | Agent 正在执行 Step 3–8 | — |
| `调研完成` | Dossier 已成稿，未核验 | 产出 `reports/<学校>/<学校>_Master_Dossier.md` |
| `已核验` | **可交付** | `verify.py` 退出码为 0；⚠️ 项已人工点击确认并改写「核验方式」列 |

> ⚠️ **`调研完成` ≠ `已核验`。** 这两者混同是本项目要解决的核心问题：
> 一份"看起来写完了"的档案，和一份"每条事实都能被第三方重新取数"的档案，
> 中间隔着的正是核验回路。
